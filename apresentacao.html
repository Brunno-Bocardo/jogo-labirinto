01 // Estado Atual

O que o jogo faz hoje

Resumo da analise do codigo atual (script.js, style.css, index.html)

⚡

Geracao de Labirinto

Usa backtracking recursivo (DFS) para gerar labirintos aleatorios 16x16. Algoritmo correto e funcional — sempre gera labirintos validos com caminhos conectados.

FUNCIONAL
♞

Sistema de Turnos

Jogador move, depois monstro move. A cada 3 turnos do monstro, o jogador escolhe entre Pilha (LIFO) ou Fila (FIFO) para definir a ordem dos movimentos do monstro.

FUNCIONAL
🎨

Renderizacao Canvas

Usa HTML5 Canvas 400x400px com celulas coloridas: roxo (jogador), vermelho (monstro), verde (chegada), cinza (paredes), branco (caminho).

BASICO
📝

Conceito Educacional

Ensina estruturas de dados (Pilha vs Fila) de forma interativa — o jogador precisa entender a diferenca para tomar boas decisoes estrategicas.

PONTO FORTE
💻

CSS Minimo

Apenas 5 linhas de CSS: flexbox no body com gap. Sem responsividade, sem temas, sem estilizacao de elementos, sem tipografia customizada.

PRECISA MELHORAR
🚧

UX com alert/prompt

Toda interacao (escolha Pilha/Fila, vitoria, derrota) usa alert() e prompt() nativos do navegador. Bloqueia a thread e quebra a experiencia.

02 // Bugs & Problemas

Problemas encontrados no codigo

Bugs reais que afetam o funcionamento do jogo

🐛

Variaveis globais implicitas

listaProxima (linha 177) e proximoMovimento (linhas 218/224) sao declaradas sem let/const, criando variaveis globais implicitas. Em strict mode, isso daria erro.

Linha 177: listaProxima = gerarMovimentos(3) — falta let

Linhas 218/224: proximoMovimento = listaAtual.shift() — falta let

BUG
🐛

Logica Pilha/Fila invertida

Pilha (Stack = LIFO) deveria usar .pop() mas usa .shift(). Fila (Queue = FIFO) deveria usar .shift() mas usa .pop(). A mecanica esta trocada!

Pilha (opcao 1): usa shift() (remove do inicio = FIFO) — deveria ser pop()

Fila (opcao 2): usa pop() (remove do fim = LIFO) — deveria ser shift()

BUG LOGICO
🐛

Conflito na primeira rodada

Nas primeiras 3 jogadas (contadorPrimeiraRodada < 3), o monstro ignora a escolha do jogador e sempre usa pop() na listaAtual. Isso consome a lista sem respeitar a decisao do usuario.

BUG LOGICO
🐛

console.log em producao

Existem 11 chamadas console.log() espalhadas pelo codigo de producao. Vaza informacao do estado interno do jogo e polui o console do navegador.

LIMPEZA
🐛

jogadasRestantes nao utilizada

A variavel jogadasRestantes (linha 87) e decrementada a cada movimento mas nunca e lida ou exibida. Codigo morto que confunde a leitura.

CODIGO MORTO
🐛

Indentacao inconsistente

O script.js comeca com indentacao extra (como se ainda estivesse inline no HTML). Mistura tabs e espacos em varios trechos.

03 // Qualidade de Codigo

Analise tecnica do script.js

Problemas de arquitetura e oportunidades de refatoracao

⚠

Duplicacao massiva

A funcao moverPersonagem() repete o mesmo bloco de 8 linhas para cada uma das 4 direcoes (linhas 262-298). Sao ~40 linhas que poderiam ser ~10.

// Hoje: 4 blocos quase identicos if (tecla === 38 && ...) { apagarPersonagem(); posicao_y--; ... } if (tecla === 40 && ...) { apagarPersonagem(); posicao_y++; ... } if (tecla === 37 && ...) { apagarPersonagem(); posicao_x--; ... } if (tecla === 39 && ...) { apagarPersonagem(); posicao_x++; ... }   // Sugestao: mapa de direcoes const direcoes = { 38: [0,-1], 40: [0,1], 37: [-1,0], 39: [1,0] }; const dir = direcoes[tecla]; if (dir && podeAndar(posicao_x+dir[0], posicao_y+dir[1])) { ... }
REFATORAR
⚠

12+ variaveis globais

Todo o estado do jogo vive em variaveis globais soltas: posicoes, contadores, listas, turno. Zero encapsulamento — qualquer funcao pode modificar qualquer estado.

let posicao_x, posicao_y; let monstro_x, monstro_y; let turno = 0; let escolha;   class GameState {   player = { x: 0, y: 0 };   monster = { x: 0, y: 0 };   turn = 0; }
ARQUITETURA
⚠

prompt() bloqueia tudo

O prompt() na linha 202 congela completamente o jogo, o rendering do canvas, e toda a thread do navegador ate o usuario responder. Pessima UX.

escolha = prompt("Escolha:\n1 - Pilha\n2 - Fila");   // Sugestao: modal HTML com botoes mostrarModal({ opcoes: ['Pilha', 'Fila'] })   .then(escolha => processarEscolha(escolha));
UX
⚠

Sem separacao de responsabilidades

Rendering, logica de jogo, geracao de labirinto, input handling e UI estao todos num unico arquivo de 316 linhas. Dificulta manutencao e testes.

Comparacao direta: o que voces planejaram vs. o que eu adicionaria

"Estruturar padrao de branches e tags"
  • Git Flow simplificado: main, develop, feature/*

  • PR templates + code review obrigatorio
Dificuldade ✔ Planejado
"Criacao de niveis de dificuldade"
  • Facil: grid 10x10, monstro lento, sem limite de movs
  • Medio: grid 16x16 (atual), mecanica normal
  • Dificil: grid 20x20, 2 monstros, menos movimentos
  • Progressivo: comecar facil, aumentar ao vencer

05 // UX & Design

Melhorias de experiencia

As maiores oportunidades de impacto visual e de usabilidade

COMO ESTA HOJE

Quadrados coloridos

Jogador, monstro e chegada sao apenas retangulos de cor solida sem nenhum detalhe visual

prompt() nativo

Escolha Pilha/Fila aparece num popup do navegador que congela tudo

alert() para feedback

Vitoria e derrota sao comunicadas com alert() sem nenhum estilo

Canvas fixo 400x400px

Nao se adapta a telas diferentes, fica minusculo em desktop grande e nao funciona em mobile

Sem feedback de acao

Nao ha indicacao visual de que o jogador ou monstro se moveu — simplesmente redesenha

COMO PODERIA SER

Sprites ou emojis com animacao

Usar drawImage() com spritesheets ou ate emojis estilizados para dar personalidade aos personagens

Modal HTML estilizado

Dois botoes grandes "PILHA" e "FILA" com explicacao visual, sem bloquear a thread

Tela de game over/vitoria

Overlay animado com estatisticas (movimentos usados, tempo) e botao "Jogar de Novo"

Canvas responsivo

Usar % do viewport ou min() para que o canvas se adapte a qualquer tela

Animacoes e som

Transicao suave entre celulas, flash na colisao, som ao andar/ser pego/vencer
